# GrapeLeafi-QQbot

本机自建 QQ 机器人框架，基于 **NapCatQQ**（NTQQ 真实会话，本机即用、无需租服务器），客户端为 Node.js 编写，内置一整套**防风控（防封号）**机制。

```
┌─────────────┐   反向 WebSocket (仅本机)   ┌─────────────────────────────┐
│ NapCat 协议端 │ ──────────────────────▶ │ Node.js 客户端               │
│ (本机 QQ 桌面版  │  ws://127.0.0.1:8181/onebot/v11/ws │ (网关+防风控+指令路由)    │
│  + 注入补丁)   │                        └─────────────────────────────┘
└─────────────┘  不开放任何入站端口
```

- 协议端 `bot/napcat/` — NapCat Shell + `config/` 下的 OneBot11 配置
- 客户端 `client/` — Node.js OneBot v11 客户端（Reverse WS 服务端 + 防封模块）
- 脚本 `scripts/` — 一键下载 / 启动

> 警告：任何形式的 QQ 自动化都有封号风险。**强烈建议使用小号（新号+日常养号）**，切勿使用常用大号。使用协议逆向方案可能违反腾讯服务条款，请自行评估风险。

## 快速上手（双击 `start.bat` 就行）

1. **启动**：双击 `start.bat`。缺依赖会自动装、缺 NapCat 会自动下载、缺 `config.json` 会自动从模板生成。
2. **扫码**：按提示用 QQ 扫 NapCat 的二维码（第一次才会弹，之后走快速登录）。
3. **开聊**：控制台在 http://127.0.0.1:9632，聊天用**另一个** QQ（见下方「唯一要手填的一项」）。

装完就能用，**不需要先跑 `install.bat`**，也不需要手改 `config.json`：
接入 token、NapCat 反向 WS 条目、机器人的昵称全都是启动时自动写好的。

### 唯一要手填的一项：`bot.adminIds`（主人 QQ）

只有 `/设置`、`/修复` 这类**主人指令**需要它，聊天/签到/图鉴/扭蛋/运势全都不需要，
所以留空也能正常玩。想用主人指令时：

- 打开控制台 →「设置」页 → 填 QQ 号 → 保存，**立刻生效，不用重启**；或
- 直接编辑 `client/config.json` 的 `bot.adminIds`。

> ⚠️ 必须填你**用来跟机器人聊天**的那个号，**不能填登录机器人的这个号**。
> 机器人会忽略自己发的消息（`brain.js` 里 `self_id === user_id` 直接 return，
> 这是防止关键字无限回环的必需判断），把机器人自己的号填成主人等于没人有主人权限。
> 也就是说：想让这个 bot 认你当主人，你手上得有**第二个 QQ**。

> **素材不随项目分发。** 图片素材基本都是别人的作品（见「素材与版权」），
> 仓库和分享包里只留 `assets/README.md` 说明怎么放。单卡包有 2GB，也确实没法塞进 Git。
>
> **但功能是带的，内容是空的。** 分享包里的 `client/data/` 是去个人化版本：
> **保留**：47 项内置功能开关、生日表（136 条公开作品角色）、事件文案、AI 人设、葡家头衔、6 个二次元图源、731 张卡的元数据。
> **清空**：你的预设指令、关键字回复、定时文案，以及群号、玩家数据（签到积分这些）、本机绝对路径。
> 别人装完是个**有全部功能、内容自己填**的 bot，不是空壳，也不是你的翻版。

## 快速开始

### 0. 准备

- **Node.js 18+**（本机已有 Node 24，无需操作）
- 首次运行会自动安装依赖：`ws`（WebSocket）与 `@napi-rs/canvas`（把 `/help` 渲染成图片，含中文字体，无需额外配置）
- **QQ 桌面版（NTQQ）**，版本 ≥ 9.9.22-40990（NapCat 打包要求，见 `bot\napcat\qqnt.json`）
  - 下载：<https://im.qq.com>
  - 若本机还没有 QQ，可改用官方一键包（内置 QQ+NapCat，自动部署）：
    ```powershell
    .\scripts\download-napcat.ps1 -OneKey
    ```

### 1. 下载/准备协议端

```powershell
.\scripts\download-napcat.ps1
```
下载 NapCat Shell 到 `bot\napcat\`（已内置完成，可跳过）。

### 2. 一键启动（三种方式任选）

**方式一：双击运行（推荐新手）**
直接双击项目根目录的 `start.bat`（自动补依赖/下载 NapCat → 启动客户端 → 启动 NapCat）。相关文件：

| 文件 | 作用 |
| --- | --- |
| `start.bat` | 主启动：先预检，再起客户端 + NapCat |
| `install.bat` | 首次配置：装依赖 + 下载 NapCat |
| `start-client.bat` | 只启动 Node 客户端 |
| `start-napcat.bat` | 只启动 NapCat 协议端（可加参数 `-QQ 123456` 快速登录） |

**方式二：命令行脚本**

```powershell
.\scripts\start-all.ps1
```

**方式三：命令行脚本-快速登录**
```powershell
.\scripts\start-all.ps1 -QQ 你的QQ号
```
1. 新开窗口启动 Node 客户端（`ws://127.0.0.1:8181/onebot/v11/ws`，反向 WS，带 token 鉴权）；
2. 当前窗口启动 NapCat（launcher 会自动请求管理员权限，定位已安装的 QQ 并注入启动）。

### 3. 登录

登录方式在 `client/config.json` 的 `bot.napcat.mode` 里选，**只用改这一个文件**，不用再动 `bot/napcat/` 里的任何文件。

| 方式 | 配置值 | 说明 | 风控 |
|---|---|---|---|
| 扫码 | `"qr"`（默认） | NapCat 打开 QQ 客户端窗口，扫码登录 | 最低 |
| 免扫码 | `"quick"` | 该号本机登录过，直接登录态进 | 低 |
| 账号密码 | `"password"` | 用 QQ 号 + 密码登录 | **高，见下** |

```json
"napcat": {
  "mode": "qr",
  "qq": "你的QQ号",
  "password": "",
  "webuiPort": 6099
}
```

- `mode: "qr"`：默认，什么都不用填。双击 `start.bat` 即可。
- `mode: "quick"`：填 `qq`。该号必须**至少扫码登录过一次**，否则没有可用的登录态。启动时自动带上 `-q <QQ>`。
- `mode: "password"`：填 `qq` 和 `password`。

命令行临时覆盖（不改配置）：`.\scripts\start-napcat.ps1 -Mode quick`、`-Mode qr`、`-Mode password`。

#### 账号密码登录的风险（建议先读完再用）

密码登录看着方便，实际代价不小：

- **风控概率明显更高。** 腾讯对密码登录的检测远比扫码严，常见结果是直接要求
  「需要验证码」或「需要新设备验证」。这两种都**必须人工在 NapCat 管理页完成**，
  本项目不会、也不应该尝试自动绕过。
- **密码是明文存着的。** 就在 `client/config.json` 里。这个文件已经加了 gitignore、
  也被分享脚本排除，但只要它泄露，QQ 账号就等于交出去了。
- **顺序建议：`quick` > `qr` > `password`。** 只要这台机器上登录过，`quick` 既免扫码
  又没有密码风险，是最省事的正常选择；`password` 只适合扫码登录不了的场景。

任何一种方式失败时，启动脚本都会**自动回退到扫码登录**并说明原因，不会卡住不动。

登录成功后 NapCat 自动接入 Node 客户端，客户端窗口出现 `协议端已接入`，随后即可在群里用 `/ping`、`/help`、`/运势` 测试。

登录后浏览器打开 **http://127.0.0.1:9632** 即可进入本地控制台（见下）。
NapCat 自带的管理页在 `http://127.0.0.1:6099`，访问 token 同样是启动时自动生成的
32 位随机值，存在 `client/config.json` 的 `bot.napcat.webuiToken`。

## 功能一览

**内置指令**（群聊/私聊都在前面加 `/`，如 `/help`、`/签到`；**群内被 @ 或喊昵称时可以省略 `/`**，例如 `@葡叶酱 禁言 @某某 5分钟` 等同 `/禁言 @某某 5分钟`；不带 `/` 的普通文本不再当成指令执行，会走关键字 / AI / 仅@ 逻辑）

| 指令 | 说明 |
| --- | --- |
| `/ping` | 存活与延迟 |
| `/help` `/帮助` `/求助` | **以图片形式**按类型分组发送帮助：每个类型只列前几条并提示「还有 N 条」，输入 `/help <类型>`（如 `/help 文娱`、`/help 积分`、`/help 抽卡`）可看该类型全部指令与说明；图片生成失败时自动退回纯文字，不会「没反应」 |
| `/运势` | 今日运势（每人每天一次） |
| `/抽签` | 从 `content.json` 指定目录随机抽一张签图并发送（带冷却） |
| `/钓鱼` `/鱼塘` `/卖鱼` | 钓鱼小游戏，仓库与金币持久化在 `client/data/games.json` |
| `/签到` `/等级` `/面板` | 每日签到+积分与光玉 / 等级档案 / 按钮卡片面板。等级图与签到图为 **原神角色面板风格**：左侧深色面板放头像、**葡家等级**进度条和双列属性网格（数值排在文字右侧），昵称右侧跟一枚**等级头衔**；右侧立绘取自该用户已抽到的**卡面**（`card` 图优先、`detail` 图兜底），抽不到卡则回退渐变 |

| `/抽卡 <池> [数量]` `/十连 [池]` | 用**光玉**抽卡。池子可写作品（`ab`）或角色名（`奏`/`由理`/`音无`…），单次最多 10 连。别名 `/十连`→`十连`。例：`/抽卡 ab`、`/抽卡 奏 10`、`/抽卡 10 ab` |
| `/卡池 [池名]` `/保底` | 查看全部卡池与单抽价格 / 查看各池 SSR 与 SR+ 保底进度 |

| `/兑换 <数量>` | 积分余额换光玉（1 积分 = `cards.json` 的 `exchange.rate` 倍，当前 **1:1**）。**只扣余额，等级与累计积分不受影响** |
| `/分解 <卡号\|全部>` | 分解重复卡换光玉：`SSR→50`、`SR→20`、`R→5`、`N→1` |
| `/光玉` | 查询光玉余额与当前积分 |

| `/开启 X` `/关闭 X` | 按「类型」或「单条指令」开关群功能（见下文「群功能开关」）；发 `/开启` 查看可选列表 |

| `/今日人设` `/土味情话` `/彩虹屁` `/舔狗日记` `/毒鸡汤` `/时间` | 文娱类：人设 / 情话 / 夸夸（后两者可 `@某人`）/ 文案 / 当前时间（默认按群关闭） |
| `/猜数字` `/塔罗` `/今日人品` `/疯狂星期四` | 互动类：1~100 猜数（`/猜 N` 出招）/ 塔罗牌（`/塔罗 N`，默认 3 张）/ 每日人品 / v50（默认按群关闭） |
| `/敲木鱼` `/功德榜` | 互动类：攒功德（可暴击，存 `merit.json`）/ 功德 Top10（默认按群关闭） |
| `/抽群友` `/轮盘` | 互动类：随机点名 / 俄罗斯轮盘（打中禁言5分钟，需 bot 是本群管理员；默认按群关闭） |
| `/戳一戳 @某人 [类型]` `/比心 @某人` `/点赞 @某人` `/回戳 @某人` | 互动类：**真动作**，走 `group_poke`/`friend_poke`/`send_poke`。**群聊用 `@某人`，私聊直接写 QQ 号**（`/戳一戳 12345678`，私聊里没有 @）。类型可选 `比心`/`点赞`/`心碎`/`666`/`放大招`，以及 9 种 SVIP 花样（`抓一下`/`碎屏`/`勾引`/`手雷`/`结印`/`召唤术`/`玫瑰花`/`让你皮`/`宝贝球`，需 bot 号是 SVIP）。`/比心`、`/点赞` 是 `/戳一戳 @某人 比心|点赞` 的简写。**注意**：花样靠 poke 消息段表达、而消息段无法指定戳谁，所以「action 负责戳到人、消息段负责换花样」是两件事，花样没发出去时机器人会明说「只戳了普通的一下」。**若指令毫无反应，先确认两件事**：① bot 是否在运行；② 互动分类是否在本群开启——`互动` 默认在 `defaultOff` 里，`groupEnabled` 只列了特定群的话其他群一律不放行，此时会回「在本群还没开启」（默认按群关闭） |
| `/拍一拍 @某人` `/捏一捏 @某人` | 互动类：只发文案。QQ 没有独立的拍/捏动作，别误以为会真戳（默认按群关闭） |
| `/天气 [城市]` `/热搜` | 联网类：实时天气（wttr.in 免密钥）/ 全网热点 Top10（默认按群关闭，接口偶发失败会友好提示） |
| `/随机二次元` | 从控制台已启用且标记为非18+的图片 API 中随机取图，失败自动换源；别名：`/随机二次元图片`、`/二次元图片`、`/随机动漫`、`/动漫图片` |
| `/群名片 [名字]` `/群名 [名字]` | 群管理：改某人名片（可 @）/ 改群名；权限同「群管理」 |
| `/我的 [@某人/QQ号]` `/信息 [@某人/QQ号]` | 查询个人资料 / 群成员资料与头衔（走 OneBot API），默认自己 |
| `/群信息 [群名/群号]` | 查询群名称/人数/群主，默认当前群（群里可省略参数） |
| `/头像 [@某人/QQ号]` | 发送头像图片，可省略（默认自己） |
| `/禁言 [@某人/QQ号] [时长]` `/解禁 [@某人/QQ号]` | 群管理，**发送者须是本群管理员/群主或主人**；目标支持 `@某人` 或直接填 QQ 号；时长支持 秒/分钟/小时/天/周（默认10分钟），如 `/禁言 123456 1小时` |
| `/踢出 [@某人/QQ号]` `/全体禁言` `/解除全体禁言` `/撤回`(回复一条消息再发) | 群管理，权限同上 |

> 所有「目标是某人」的指令都同时接受 **@某人** 与 **QQ 号** 两种写法，例如 `/禁言 @某某 10分钟` 与 `/禁言 123456 10分钟` 等价。

> 群管理类指令会先校验发送者身份：**本群管理员/群主**、配置里的 `adminIds`（主人），或被主人**授权**过的账号才执行，否则回复「权限不够」。bot 自身也需要是该群管理员才能执行成功。

**主人与授权（隐藏指令，仅主人可用）**
- 主人 = `client/config.json` 的 `bot.adminIds`（填自己的 QQ 号），拥有全部权限，且不受深夜静默/频率限制。
- `/给予 [@某人/QQ号] 管理员` — 授予「bot 管理员」，等同于本群管理员能用的全部指令；
- `/给予 [@某人/QQ号] 禁言,踢出` — 只授予单个权限，可选：`管理员`/`禁言`/`解禁`/`踢出`/`全体禁言`/`解除全体禁言`/`撤回`（逗号或空格分隔）；
- `/剥夺 [@某人/QQ号] [权限...]` — 剥夺指定权限，不写权限则剥夺其全部；
- `/权限 [@某人/QQ号]` — 查看某人当前的 bot 权限。
- 该授权**只作用于 bot 指令**（相当于 bot 内的白名单），不会给对方真实的 QQ 群管理身份；授权记录持久化在 `client/data/permissions.json`。这些指令不会出现在 `/help` 里（隐藏），非主人发送时被当作普通消息忽略。

> ⚠️ **`/给予` 和 `/发放` 是两个不同的指令，别搞混**：
> - `/给予 @某人 管理员` → **权限**系统（授权对方能用什么指令）
> - `/发放 积分 100 @某人` / `/发放 光玉 500 @某人` → **货币**系统（直接加减积分/光玉）
>
> `/发放` 的完整用法：`/发放 <积分|光玉> 数量 [@某人]`；数量写负数即扣回（`/发放 光玉 -50 @某人`）。两者都是 `ownerOnly`，非主人发送会被静默忽略。

**聊天回复**
- **私聊**：白名单内的人随便聊，非指令内容交给 AI；AI 没配就用兜底话术；
- **群聊 @它 或喊昵称**：后面跟着的如果是可用指令，直接执行（不用再打 `/`，如 `@葡叶酱 运势`）；不是指令则交给 AI；
- **群内是否自动接话**：在控制台「回复设置」里选。默认「自由回复」——群内没被点名也会对关键字/问候词`接话；选「仅 @ 回复」后，群里必须 `@它` 或喊昵称（或输入 `/` 指令）才回复，避免误触发；同页可设「关键字长句上限」（`keywordMaxLen`，0=不限制，默认不限；填 N 则超过 N 字的消息不再触发 包含/正则 关键字，防止长文本误触发）；同页还有「**回复时引用原消息**」（`settings.replyQuote`，默认勾选=沿用协议端「回复某条消息」的引用样式；取消后指令/关键字/AI 回复一律**直接发送不引用**）；
- **指令与预设回复不走 AI**，直接按 `content.json` 的配置回复，零延迟零成本；
- **预设指令支持模板占位符**：回复文案里可用 `{args}`(全部参数)、`{1}~{9}`(第n个参数)、`{rand:1,100}`(区间随机整数)、`{at}`(@回复发送者)、`{target}`(@被@的人，实现「冲 @某人」这类交互指令)、`{targetqq}`、`{qq}`/`{nick}`/`{gid}`、`{date}`/`{time}`，以及**权限类占位符**：`{role}`(发送者身份：主人/管理员/群主/群管理/成员)、`{ifadmin:A|B}`(发送者是 主人/被授予管理员/群主/群管理 时输出 A 否则 B)、`{ifowner:A|B}`(只判是否主人)；还有**动作占位符**：`{ban}`/`{ban:5分钟}`、`{unban}`、`{kick}`(对被@的人执行)、`{banall}`/`{unbanall}`(全体禁言开关)、`{recall}`(撤回你回复的那条消息)，仅群聊且仅管理员执行、文字本身不会显示；还有**卡片/签到类占位符**：`{panel}` 让回复自带官方按钮卡片(签到/钓鱼/运势/等级，协议端不支持时 `/面板` 自动降级为文字列表)、`{signday}` 对触发者执行签到并附一张实时生成的签到卡(头像/等级/积分/连续天数，base64 内联发送，即发即弃不落盘)。例：回复填「{nick} 掷出 {rand:1,6} 点」即可实现 `掷骰` 指令，「已成功灌注 {target} {rand:50,500} 毫升」收到「灌满 @某人」就会把**被@的人**转成 @ 段并回随机毫升数；**`{args}` 可做「传话筒」**：指令名填 `说`、回复填 `{args}`，群里发 `@葡叶酱 说 喜欢你`（或 `/说 喜欢你`）它就原样回「喜欢你」；关键字回复同样支持（无参数变量）。每条指令还可配**别名**（`aliases`，逗号分隔）与帮助简介 `desc`（`/help` 图片里展示）；复杂逻辑指令继续用代码内建（控制台不需覆盖）。
- **HTTP 接口指令**：预设指令可绑定一个 URL，启用后该指令把参数/消息内容（JSON POST 或 GET Query）发给该地址，把**返回内容作为回复**——返回纯文本→直接回；返回 JSON 数组或 `{message}` / `{messages:[...]}` → 每条一条消息，多条第**默认合并转发**成一条（取消勾选则逐条发）。常用于：把文字/图片交给外部服务处理（AI 画图、翻译、OCR、风纪检查、你自己写的脚本接口等），或**仅管理员**的指令作为远程管理操作入口。请求体会带 `command/user_id/group_id/nickname/text/images[]/date/time`，可配 Authorization Token（Bearer）；调用失败会回复失败原因。所有指令仍先过 冷却/权限(仅管理员)/群限制/静默 这些既有闸门。
- **群内自建指令**（每个群独立，互相看不见）：群成员 @bot 说「**添加指令 名字 回复内容**」即可新增，之后在该群直接发「名字」就自动回复对应内容（例：`@bot 添加指令 寄寄 寄寄富` → 群里发「寄寄」回「寄寄富」）；发「**本群指令**」查看本群已有哪些；发「**删除指令 名字**」删除。（等价写法：`新增指令`/`教我`、`移除指令`/`忘记`、`查询指令`/`自定义指令`/`群指令`；回复内容同样支持模板占位符。）保存进 `content.json` 的关键字列表（标记「本群」，限定群=该群）；频率限制：每人 10 秒一条、每天最多 20 条，管理员不受限。
- **关键字回复**：`content.json` 里配的关键词命中就自动接话（可在控制台增删）。**一条回复支持多个关键字**（用 `matches` 数组，控制台里**一个关键字一行**，任一命中就触发；同一行用 `/` 分隔也可，如 `说/复述`；老数据只有 `match` 时以它为准）。**`{args}` 在关键字里=命中词后面的内容**：如关键字 `说`（包含）回复 `{args}`，发「说 喜欢你」就回「喜欢你」（关键字无需 `/` 或 @ 也能触发）。支持**多种触发条件**：`contains`(包含) / 整句(默认) / `useRegex`(正则) / `mentionOnly`(仅被@时) / `adminOnly`(仅主人或管理员触发)；命中后可用**随机多条**（每次随机取一条）、**图片**（本地路径或 http 链接）或**整句复读**（`repeat:true` 回触发句），还可用 `excludeWords` 设置命中即忽略的排除词。冷却填 `0` 表示**不冷却**（未填默认 60 秒，预设指令默认 5 秒）。

- **关键字随机发本地图库**：关键字卡片里除「图片」外还有「**图库目录**」。填目录后每次命中会从**整个图库随机抽一张**发出来（纯随机，不保证不连续重复）。规则：
  - **递归扫描**全部子文件夹，支持 `png` / `jpg` / `jpeg` / `gif` / `webp`（大小写不敏感），非图片文件自动忽略；最大深度 6 层、最多 5000 张。
  - **可填多个目录**，用**分号或换行**分隔，几个目录的图片会**混在一起**随机；适合「角色图库」「作品图库」分别建不同关键字。
  - 目录按你的习惯分类即可，**建议直接用文件夹分类而不是数据库**：`图库\作品名\角色名\xxx.jpg`。图库本身已经是文件，文件夹分类零维护、拖进来就生效、备份/迁移就是拷目录；只有当你需要「每张图带标签/权重/冷却/单独开关」这类元数据时，才值得上数据库（那时把索引存 `data/` 下的 json 即可，原图仍然留文件夹）。
  - 文件列表**缓存 60 秒**，所以刚放进新图最多一分钟生效；删图同理。想立刻生效就等一分钟，或重启客户端。
  - 「图片」和「图库目录」**同时填时以图库目录为准**。只填图库目录、不填文字也可以触发（修掉了以前纯图片关键字不响的问题）。
  - 抽中的图会走和抽签图一样的处理：压到 **1080px 宽 / JPEG q82** 后以 `base64://` 内联发送，不落地、不受本地路径权限影响。
  - 卡片上有「**扫描预览**」按钮，保存前可以先看扫到几张图、有没有进错目录。
- **分时段问候（早安/晚安等）**：预设指令与关键字都可以给「早 / 午 / 晚 / 夜」四个时段分别填文案（早 5-11、午 12-17、晚 18-21、夜 22-4，边界与代码 `timeReplyFor` 一致），回复时按**服务器当前时间**自动选用对应文案，没填的时段用「回复(默认)」兜底。`content.json` 里已默认配好「早安」「晚安」「晚上好」三条**关键字**（注意是关键字，**不带 `/`**，直接在群里发「早安」就触发，不是 `/早安` 指令）——但这三条只存在于**你自己这份** `client/data/content.json`；`share.bat` 生成的去个人化模板会把关键字和预设指令整块清空，拿到包的人自己在控制台「关键字回复」页加。

| 名称 | 存哪 | 怎么涨 | 怎么花 | 会不会影响等级 |
| --- | --- | --- | --- | --- |
| **积分余额** `points` | `checkins.json` | 签到（`+10 + min(连续天数-1, 10)`，即 10~20/天）、`/发放 积分 +n` | `/兑换 <n>` 换光玉、`/发放 积分 -n` | **不会** || **累计积分** `earned` | `checkins.json` | **只有签到才加**（`/发放 积分` 不算，那是余额不是累计），**只增不减** | 不可消费 | **是升级的唯一依据** |

### 存档的耐久性保障

所有 `data/*.json` 都经由 `client/src/storage.js` 这一个入口读写，因此数据安全策略只需在一处实现。目前具备：

| 机制 | 做法 | 防的是什么 |
| --- | --- | --- |
| **原子写** | 先写同目录 `.tmp`，fsync 后 `rename` 覆盖 | 读到写了一半的文件；崩溃损坏主文件 |
| **落盘同步** | rename 前后分别 fsync 数据文件和目录项 | 掉电后「文件名更新了但内容是空的」 |
| **滚动备份** | 覆盖前自动备份到 `data/backups/<文件名>/<时间戳>.bak`，**保留最近 5 代** | 逻辑错误、误编辑、磁盘故障导致的数据丢失 |
| **损坏即停** | 解析失败时把坏文件改名成 `<文件名>.corrupt-<时间戳>` 并**中止启动**，绝不静默回退成空数据 | **静默清零**——这是最隐蔽的数据丢失方式：文件坏了 → 空状态启动 → 第一次保存把坏文件覆盖 → 原始数据永久消失 |
| **脏检查** | 内容与磁盘一致时跳过写入 | 无谓的全量重写（`content.json` 有 3MB） |
| **版本门** | `checkins.json` / `cardgame.json` 顶层 `__v` 决定是否跑迁移 | 每次启动都把老档案按兜底值重算一遍这类隐式改写 |

**恢复步骤**：存档报「解析失败」时，先看 `data/backups/<文件名>/` 下时间戳最新的那一份，把当前文件改名留档（别直接删），再把备份复制成原文件名，然后启动。程序会在报错信息里直接给出备份目录路径。

**备份限流**：同一文件 5 分钟内只备份一次（可用环境变量 `BOT_BACKUP_INTERVAL_MS` 调，`BOT_BACKUP_KEEP` 调保留代数）。这是为了避免高频保存时把 I/O 全花在复制上——`content.json` 单份就 3MB，3MB × 5 代每次都复制不可接受。注意这个限流意味着**进程刚启动的前 5 分钟内还没有备份**，那期间只有原子写保护。

**故意没做校验和清单**：这些存档需要人工手改，一改就与清单不符，天天误报等于没报警。损坏检测交给解析校验，覆盖真实的截断/损坏场景。

`defaultOff` 当前为 `["生日","文娱","互动","联网"]`——**主人（`adminIds`）豁免开关限制，默认关闭的指令主人也能直接用**；普通成员需先用 `/开启 文娱`（类型）或 `/开启 钓鱼`（单条）在本群打开，`/关闭 X` 再关掉；记录存于 `settings.groupEnabled`（键 `cat:类型` / `cmd:指令`），控制台「回复设置」页可整体编辑；被关闭的指令会回复提示「还没开启」，不会崩。当前已开启的记录：`cat:生日`、`cat:互动`、`cat:联网`、`cat:文娱`、`cmd:随机二次元`。

**帮助指令分层**：`/help`（别名 `/帮助` `/求助`）以图片形式把内置指令按类型分组，**每个类型只列前 5 条**并给出「还有 N 条 → `/help <类型>`」的提示；`/help <类型>` 展开该类型全部指令。共 12 个类型：`基础` `积分` `日常` `抽卡` `小游戏` `查询` `生日` `文娱` `互动` `联网`，管理员额外多一个 `群管理`，有自定义预设指令时多一个 `自定义`。其中 **`/help 积分`** 是专页，讲清「余额 vs 累计积分」「100×N 升级规则」「兑换不掉级」「抽卡只扣光玉」。类型名支持别名和大小写/空格/emoji 归一化（`/help 打卡`、`/help cards`、`/help 管理` 均可），传入不存在的类型会列出所有可选类型而不是报错。图片生成失败（缺 `@napi-rs/canvas` 等）时**自动退回纯文字**，不会出现「没反应」。

**群事件回应**：入群欢迎 / 退群提示 / 戳一戳回应 / 精华 / 管理员变动 / 禁言（`settings.events`）。**「启用群」留空 = 所有群生效**；要只对个别群生效才填群号（逗号分隔）。文案支持占位符：`{qq}` `{nick}` 成员、`{player}` 戳你的人、`{action}` 动词。入群/退群触发 OneBot 的 `group_increase`/`group_decrease`；戳一戳触发 `notify(poke)`，群内戳 bot 才会回（好友戳需在控制台勾「允许私聊」，默认关，防被骚扰）。加好友自动通过由「加好友自动回复」文案控制，**留空 = 不自动通过**。

### 控制台安全边界（分享前必读）

控制台是**只给主人自己用的后台**，不是给普通用户的产品界面：它能改全部 `config.json`、看群列表、调主人 QQ 号，还能通过素材接口读本机图片文件。所以：

- **不要把控制台地址分享给普通用户**，也不要把访问 token 发出去；
- **不要做端口转发把它暴露到公网**。异地访问请走 VPN / Tailscale；
- 只在**自己信任的 Wi-Fi** 下用局域网地址打开，用完把 `host` 改回 `127.0.0.1` 最省心；
- 页面响应统一带 `Referrer-Policy: no-referrer` / `X-Frame-Options: DENY` / `X-Content-Type-Options: nosniff`，`?token=` 在页面加载后会**立刻从地址栏抹掉**（只留在内存里），避免留在浏览器历史或被当成 Referer 带出去；同一来源连续输错 token 达 8 次会**锁 2 分钟**，防止局域网内被暴力猜。

**想让别人用这个机器人？** 正确姿势不是把控制台发出去，而是把机器人**拉进对方的群**、把对方加进 `replyGroups`（或设 `replyPrivate: "all"` 开放私聊），需要的话在控制台「群门控」里单独给这个群配规则。对方直接用 QQ 和机器人聊天即可，全程不接触控制台。

## 防风控清单（务必阅读）

> 风控 = 腾讯对账号/群消息的限制，严重时封号。选型（真实 QQ 会话）只是基础，**使用习惯决定生死**。

**发送侧（客户端已自动实现，`client/config.json` 可调）**
- 并发发送：最多 `concurrency`(3) 条同时发送；**同一群/同一人严格排队串行**，不同群/不同人互不阻塞——某条大图上传慢，也不会卡住其它会话；
- 全局随机节奏：每条 bot 消息之间至少间隔 `minDelayMs~maxDelayMs`（默认 0.6~1.8 秒随机）；
- 同群/同人冷却：刚给某群/某人发过，`groupCooldownMs`/`userCooldownMs`（默认 3 秒）内同目标排队等待（不丢，只是稍后发）；
- 突发限流：`burstWindowSec`(60s) 内最多 `burstLimit`(20) 条，超出自动排队等待；
- 小时上限：`hourlyCap`(120) 条/小时，超出自动排队等待；
- 每日上限：`dailyCap`(500) 条/天；每群每日 `groupIdDailyCap`(200) 条/天，超出直接丢弃；
- 重复抑制：`sameTextGapMs` 默认 **0 = 关闭**（不再丢弃重复文本）。想开启就设成毫秒数（如 `60000`），只对**同一会话**的相同文本生效（不同群互不影响）；
- 发送超时：`sendTimeoutMs`(**当前 120s**，默认 120000，兼容大图上传) 内没等到协议端回执才算失败——网络/超时类失败会自动重试 1 次（间隔 2s），连续失败才累计；
- 自动退避：发送被腾讯拒绝时惩罚倍率翻倍，最高 `maxPenalty`(4x)，冷却随之拉长；成功一次即恢复；失败连击超过 5 分钟无新失败自动清零，不累计旧账；
- 软静默（风控熔断）：连续 `autoMuteFailStreak`(3) 次发送失败 → `autoMuteMinutes`(5 分钟) 内不再外发；可在控制台「状态与日志」一键重置；
- 队列保护：`maxQueueLength`(200) 满时新消息直接丢弃（不堆积）；等待超过 `maxQueueWaitMs` 的任务作废；
- 长文本截断：`maxTextLength`(500) 以上截断，避免一次性大段刷屏；
- **可视化**：控制台「风控·节流」页可直接覆盖上述绝大多数参数（含 `setRuntime`），保存后实时生效并写进 `content.json` 的 `settings.riskgate`，不必改配置重启。

**接收侧（客户端 Brain 已实现，同样可在 `client/config.json` 调）**
- 私聊白名单：模板里是 `replyPrivate:"all"`（开箱即用，陌生人私聊也会回）；收紧成 `"whitelist"` 后只有 `adminIds`/`privateWhitelist` 里的 QQ 能私聊触发。**注意**：`whitelist` + 两个名单都空 = 所有私聊被静默丢弃（日志里只有一行 `[gate] 私聊对方不在白名单`），这是「能收不能回」的头号原因；
- 深夜静默：`quietHours.enabled` 默认 **false（已关闭）**；想开启就设为 `true`，并可用 `start`/`end`（默认 23:30~06:30）与 `allowGroups` 白名单（主人不受限）；
- 群回复节流：`groupReplyGapMs`(3s) 只作用于**未被点名时的自动接话**（关键字）；指令（`/xxx`）与 `@bot`/喊昵称一定会回，不会被群里别人的闲聊“吃掉”机会；
- 用户频率上限：`userRateLimit`(300s/20) 内每个用户最多触发 20 次回复，防单人在群里连发指令刷屏（管理员不受限）；
- 忽略 at-all：消息含 `@全体成员` 一律忽略，防止被全员艾特恶意联动；
- 忽略自身消息：OneBot 上报的自身消息（`report_self_message`）不处理。

**账号侧（需要你自律）**
1. **用养好的小号**，不要用大号/常用号；
2. 登录方式用**手机扫码**（不要在没验证过设备的机器上频繁登录）；
3. **稳**是第一原则：固定设备、固定网络、尽量固定时间段在线；
4. 不要一开机就大批量加群/拉好友；新账号先正常聊天养几天再挂 bot；
5. 上线初期把 `minDelayMs/maxDelayMs/groupCooldownMs` 调大，观察三天无异常再逐步收紧；
6. 避免发营销/广告类内容（最容易风控），也避免秒回一切；
7. 手机上偶尔正常手动使用该账号，保持真人活跃特征。

**网络安全侧**
- 反向 WS 只连接 `127.0.0.1`，**本机不开放任何入站端口**，token 与客户端一致才授权；
- NapCat WebUI 已改为只监听 `127.0.0.1:6099`（见 `bot\napcat\config\webui.json`），不要把端口暴露到公网。

| `bot.napcat.qq` | `quick` 必填 | 要免扫码登录的 QQ 号 |
| `bot.napcat.password` | `password` 必填 | QQ 密码。**明文存储，泄露等于账号被接管**，详见「账号密码登录的风险」 |
| `bot.napcat.webuiToken` | | NapCat 管理页 token，**留空即可**，启动时自动生成 32 位随机值 |
| `gateway.accessToken` | | 接入 token，**留空即可**，启动时自动生成并同步到 NapCat |
| `gateway` | | 端口/path（8181），必须与 NapCat 反向 WS 一致 |
| `bot.commandPrefix` | | 指令前缀（默认 `/`） |
| `bot.replyGroups` | | 留空=所有群应答；填群号数组=白名单 |
| `bot.replyPrivate` | | 私聊策略：`all`(默认，开箱即用)/`whitelist`/`off`。收紧成 `whitelist` 时记得同时填 `bot.adminIds` 或 `bot.privateWhitelist`，否则私聊全被静默丢弃 |
| `bot.privateWhitelist` | | 允许私聊的用户 QQ 数组 |
| `bot.groupReplyGapMs` | | 群内**自动接话**（关键字）的最小间隔(ms)；指令与 `@bot` 不受此限 |
| `bot.keywordAutoReply` | | 是否启用关键字自动回复（默认 true） |
| `bot.quietHours` | | `{enabled, start:"23:30", end:"06:30", allowGroups:[]}` 深夜静默（主人不受影响） |
| `bot.userRateLimit` | | `{windowSec, max}` 每用户触发频率上限（主人不受影响） |
| `bot.ai` | | `{enabled, baseUrl, apiKey, model, temperature, maxTokens, timeoutSec, cooldownSec}` AI 接入 |
| `bot.games` | | `{lotteryCooldownSec, fishingCooldownSec, fortunePerDay}` 小游戏参数 |
| `console` | | `{enabled, host:"127.0.0.1", port:9632, token:""}` 本地控制台（token 非空时需带 `?token=`，页面加载后会自动从地址栏抹掉；`host` 改成非本机地址时**必须**配 token，否则启动即报错。改成 `0.0.0.0` + token 后手机同 Wi-Fi 即可访问，详见「控制台安全边界」） |

| `antiRisk.*` | | 其余防风控参数（`minDelayMs`/`maxDelayMs`/`groupCooldownMs`/`userCooldownMs`/`burstLimit`/`burstWindowSec`/`hourlyCap`/`dailyCap`/`groupIdDailyCap`/`sameTextGapMs`/`autoMuteFailStreak`/`autoMuteMinutes`/`maxQueueLength`/`maxQueueWaitMs`/`maxTextLength`，见「防风控清单」） |

**没有任何一项是必填的。** 三个 token 全部留空，程序启动时会自动生成并
同步到 `bot/napcat/config/`，NapCat 那边的反向 WS 条目**没有也会自动建一条**
（以前只改 token、从不建条目，于是全新装必然是「控制台永远未连接 + 所有回复失效」，
而且一行日志都不打）。所以你**不需要再去 NapCat 的配置文件里手动对一遍**——
以前这一步最容易漏，两边不一致的表现只是静默重连，很难查。

机器人的昵称也会自动认领：首次连上协议端时用 OneBot 的 `get_login_info` 把你扫码登录的那个
QQ 的昵称取回来写进 `bot.nickname`。

`bot.adminIds` 同样不是必填——它只影响 `/设置`、`/修复` 这类主人指令。
要填就填**你用来跟机器人聊天的那个号**，别填登录机器人的号（机器人会忽略自己发的消息）。

密码是唯一的例外：`password` 模式必须你自己填，且是明文。

**哪些改动热生效**：在控制台「设置」页保存后，`bot` 段（主人、昵称、前缀、白名单、免打扰、频率限制、AI、游戏冷却）与 `scheduler` 段**立即生效**，不用重启。
**必须重启**：`gateway` 监听地址/端口/path、`console` 自身配置、`antiRisk` 全部数值——这些在进程启动时绑定或构造，改了不重启不生效。

`version` 当前为 2。顶层字段：

| 字段 | 说明 |
| --- | --- |
| `packs[]` | 卡包：`id`(短名，`/抽卡` 用它)、`name`、`com`(群号)、`assetRoot`(素材根目录)、`currencyName`(默认「光玉」)、`price`(单抽价格，默认 5)、`works`、`characters`、`cards`、`rates` |
| `works{}` | 作品池：`{ name, currencyName, price, aliases[] }` |
| `characters{}` | 角色池：`{ name, en, work, aliases[] }` |
| `cards{}` | **每张卡的元数据**，键是卡号：`{ "100": { character:"hisako", rarity:"SR", work:"ab" } }`。当前 731 条。**缺 `rarity` 一律按 `N` 处理** |
| `rates` | 各池概率/保底，形如 `{"work":{ssr,sr,r,ssrPity,srPity},"char":{...}}`。**留空 `{}` 时用代码默认值**（即上表），控制台改过才写这里 |
| `decay` | 分解回收光玉：`{"SSR":50,"SR":20,"R":5,"N":1}` |
| `exchange.rate` | `/兑换` 兑换倍率，1 积分 = 多少光玉（当前 1） |

**`assetRoot` 现在只写相对 `assets/` 的短路径**，例如 `"cards/ab"`。
以前写的是项目外的绝对路径，换台机器就得手动改一遍，改漏了表现为「图鉴全空」但没有任何报错。
绝对路径仍然支持（老配置不用改），三种写法都认：

| 写法 | 结果 |
| --- | --- |
| `"cards/ab"` | `<项目根>/assets/cards/ab`（推荐） |
| `"${assets}/cards/ab"` | 同上，显式写法 |
| `"D:\Media\MyCards"` | 原样使用，适合素材放在项目外 |
| `""` 或 `"******"` | 空，表示还没配，对应功能安静地不显示图，不报错 |

素材按 `assetRoot/{Icon,Card,Detail}/<卡号起-卡号止>/` 分目录存放，命名约定为
**Icon=`<卡号>i.png`**、**Card=`<卡号>.png`**、**Detail=`<卡号>d.png`**。

两处比文档更宽松的地方（都是被现实打出来的）：

- **编号区间不必严格按 30 一段。** 代码按实际区间匹配，`721-731` 这种尾段也能用。
- **文件名里的编号补不补零都行。** `001i.png` 和 `1i.png` 都能识别——
  1~99 号卡以前因为被补成三位而匹配不到，整段图鉴是空的。

完整目录结构和素材分类见 [`assets/README.md`](assets/README.md)。当前只有 1 个卡包 `ab`，
**素材为第三方所有，不随项目分发**。

## 主人专用数据修复指令

存档出问题时，**不用停客户端、不用手改 JSON、不用 SSH**——在群里 @机器人 就能改。
所有指令都要求发送者是**主人**（`config.json` 的 `bot.adminIds`），别人发会被忽略。
**每次修改前都会自动备份对应存档到 `data/backups/`，改错了可以用备份回退。**

指令统一格式：`/指令 @某人 参数`。游戏/签到类的 `@` 是**要改的那个人**（不 @ 就是你自己）。

**积分类**

| 指令 | 作用 |
| --- | --- |
| `/设积分 @某人 N` | 直接设可消费余额 `points` |
| `/设光玉 @某人 N` | 直接设光玉余额 `stones` |
| `/设等级 @某人 N` | 直接设**累计积分** `earned`（等级按累计算，不是按余额） |
| `/设功德 @某人 N` | 直接设功德数值 |

**签到类**

| 指令 | 作用 |
| --- | --- |
| `/改签到 @某人 连续=5 天数=12 总天数=30 最长=10` | 逐项改，只写要改的项 |
| `/改签到 @某人 上次=2026-09-25` | 把「上次签到日」改成指定日期（回填漏签用） |
| `/重置签到 @某人` | 签到全部清零（余额/累计一起清） |
| `/删用户 @某人` | 从签到/卡牌/游戏/功德里彻底删掉此人 |

**卡牌类**

| 指令 | 作用 |
| --- | --- |
| `/设保底 @某人 抽卡工作-常驻 sr=30 ssr=90` | 改保底计数；只写 `sr=` 或只写 `ssr=` 时另一项保持不变 |
| `/设保底 @某人 抽卡工作-常驻 清空` | 清掉该池子的保底计数（慎用） |
| `/设卡数 @某人 圣杯 1 3` | 设某张卡的数量（1=持有数 2=突破数 3=星数） |

**游戏类**

| 指令 | 作用 |
| --- | --- |
| `/设金币 @某人 12345` | 设钓鱼金币 |
| `/设鱼获 @某人 鲤鱼 3` | 设某种鱼的持有数量 |
| `/设鱼获 @某人 清空` | 清空整个鱼篓 |
| `/清冷却` | 清掉本群所有游戏冷却（抽签/钓鱼/运势） |

**存档维护类**

| 指令 | 作用 |
| --- | --- |
| `/立即备份` | 立刻强制生成一份存档备份（可选参数：签到/卡牌/游戏/功德/权限） |
| `/备份列表` | 列出各类存档已有的备份，最新 10 条 |
| `/数据概览 @某人` | 一次看完这人的签到、光玉、保底、金币、鱼篓、功德、权限 |

> **「设保底」和「设卡数」要先知道卡池标识和卡名。** 卡池标识在控制台「卡牌信息库」里能看到；
> 拿不准就先 `/数据概览 @某人`，保底计数会直接列出来。

**改之前建议**先跑一次 `/数据概览 @某人` 记下原值，改完再跑一次对比。
误操作了不用慌：对应存档的备份在 `client/data/backups/` 里，按上面「存档的耐久性保障」的恢复方法回退即可。

## 分享给别人 / 二次部署

一句话：**双击 `share.bat`**，它会在项目旁边生成一份 `GrapeLeafi-QQbot-share` 目录，
你的 QQ 号、token、全部用户数据、整套 NapCat 都已经剔除，产物只有 1MB 左右，可以直接发出去。

```
双击 share.bat
  └─ 自动剔除 ── client\config.json    你的 QQ 号 / 网关 token / AI key
                 client\data\          签到积分、卡牌收藏、生日表、群设置等全部用户数据
                 bot\                  整套 NapCat（config\ 里是按 QQ 号命名的登录态）
                 node_modules\         依赖，别人 npm install 就能重建
  └─ 自动复查 ── 产物若仍检出个人信息，直接删掉产物并报错，绝不让你误发
```

想让别人直接拿到 zip：把命令改成 `share.bat --zip`。
产物目录已存在时想覆盖：加 `--force`。

### 别人拿到之后（约 5 分钟，全程不用改代码、不用改配置）

1. 解压；
2. **双击 `start.bat`**（自动装依赖 + 下载 NapCat + 从模板生成 `config.json`）；
3. 按提示用 QQ 扫码登录 NapCat（第一次会弹二维码）；
4. 用**另一个 QQ** 私聊机器人或拉它进群，发 `/ping`、`/签到`、`/help` 试一句。

到第 4 步就已经能用了：接入 token、NapCat 的反向 WS 条目、机器人的昵称都是启动时自动写好的。

**想要主人权限**（改设置、数据修复指令）时再补一步：控制台「设置」页填
`bot.adminIds`，保存立刻生效。填**你用来跟机器人聊天的那个号**，不是登录机器人的号。

> 首次运行即使忘了建 `config.json` 也不会崩：程序会自动套用 `config.example.json` 启动，
> 控制台能正常打开，在网页里填完保存就落成真正的配置文件了。
> 但**语法错误不会被静默吞掉** —— 真坏了会直接报错停下，绝不拿默认值覆盖你的原文件。

### 手工检查

```
node scripts\leak-scan.mjs              检查当前目录能不能直接分享（不能，会列出问题）
node scripts\leak-scan.mjs <某目录>      检查某个副本干不干净
```

它会揪出：混进来的 `config.json` / `bot\napcat\` / `assets\` / `node_modules\` /
`client\data\backups\`、任何 `.bak` 自动备份、疑似密钥的 32 位十六进制串、
7~11 位的真实号码、暴露盘符的绝对路径（**正斜杠反斜杠都认**）、`file://` 与 UNC 网络路径。
哈希常量、PowerShell 注册表路径（`HKLM:\...`）、占位号、文档里的通用示例路径不会误报。

> **`client/data/` 是条件规则，不是无条件禁掉。** 那个目录里混着两种东西：
> 公开的结构性内容（生日表、事件文案、AI 人设、头衔、图源、卡池元数据 —— 该分享）
> 和只属于你的东西（预设指令、关键字回复、定时文案，以及按真实 QQ 号做键的签到积分抽卡 —— 绝不能分享）。
> 整个禁掉的话，别人装完是个**什么都没有的空壳**。
> 所以 `share.bat` 会生成一份**去个人化的数据模板**：功能留下、内容清空、群号清空、玩家数据留空壳，
> 然后严格校验产物里一个号码、一个本机绝对路径都不剩（5 位起步，比这里的 7 位规则更严）。
> 扫描时 `client/data/` 里带号就判错，并指出是哪个文件带号。

> **`assets/` 在扫描规则里是禁止项，但允许保留 `assets/README.md` 和空目录占位文件。**
> 也就是说：分享包和 GitHub 仓库里只留素材怎么放的说明，不带任何图片。

### 用 git 的话

仓库根目录的 `.gitignore` 已排除 `config.json`、`client/data/`、`bot/`、`assets/` 里的图片、`node_modules/`、日志和备份，
正常 `git add .` 不会误提交隐私。但**注意它只对 git 生效**——
打包 ZIP / 拷文件夹 / 发网盘时它一行都不管，那些隐私会原封不动跟着走，所以那种场景请用 `share.bat`。

> **走 GitHub 时 `client/data/` 整个是空的**（`.gitignore` 排除 + 里面都是本地数据）。
> 想要 GitHub 上也有配置模板，把 `share.bat` 生成的 `-share` 目录推上去，
> 那里面的 `client/data/` 已经是去号版本了。

`.gitignore` 里所有目录项都写成 `xxx/*` 而不是 `xxx/`，这是刻意的：
git 遇到被排除的目录就不再往下遍历，此时对目录内文件的 `!` 反向包含是**无效**的
（Git 官方文档明确说明父目录被排除时无法重新包含其中文件）。

## 维护提示

- **改 `client/data/` 之前先停客户端**。运行中的进程持有内存状态，退出或下次签到时会把旧状态写回覆盖你的修改（这个坑已经踩过一次：修好的签到进度被旧进程冲掉了）。好消息是现在写入前会自动备份到 `data/backups/`，且存档损坏会直接中止启动而不是静默清零——但被旧进程覆盖属于「写入了合法但过期的数据」，备份也救不回你想要的版本，所以还是先停。
- **`data/backups/` 是自动生成的恢复点**，删掉不影响运行，只影响找回能力。恢复方法见上面「存档的耐久性保障」。
- **改存档结构记得升 `__v`**：`checkins.js` 的 `SCHEMA_VERSION` / `cards.js` 的 `__v`，并在迁移函数里补对应分支，否则迁移要么不跑要么每次启动都跑。
- 仓库根目录已有 `.gitignore`（排除 `config.json`、`client/data/`、`bot/`、`node_modules/`、日志、备份），**第一次提交前务必 `git status` 确认没有隐私文件被带进去**——`config.json` 和 `client/data/` 里是你的 QQ 号与全部玩家数据。
- **本项目没有正式的测试命令**（`package.json` 无 test 脚本），改动是用临时脚本跑的回归。脚本放在 `%TEMP%\opencode\*.test.mjs`，**未纳入仓库**。
  > ⚠️ **这些脚本会丢。** 它们只存在于系统临时目录，某次环境重置/磁盘清理就没了（本项目已经实际发生过一次，840 项回归脚本全被清空）。
  > 想长期维护就**把它们挪进仓库**（比如 `client/test/`），并在 `package.json` 加个 `test` 脚本指向一个批量运行器。
  > 目前仅存两个：`datatemplate.test.mjs`（去个人化数据模板 + 泄漏扫描规则，58 项）、`share-smoke.test.mjs`（分享产物冒烟：结构、内容加载、抽签空目录降级、内置功能开关，37 项，需传产物目录参数）。
  > `storage-backup` 必须以 `BOT_BACKUP_INTERVAL_MS=0` 跑（它要绕过 5 分钟备份节流来验证轮转上限），`storage-throttle` 相反要用默认值。跑错会得到 3 个假失败。
  > PowerShell 的执行策略默认禁止执行 `.ps1`，回归请逐个 `node xxx.test.mjs` 跑，别指望双击脚本。
- **控制台前端是字符串拼接的，别改 `console/page/*` 以外的拼接逻辑**：`src/console/page.js` 把 `page/01..08` 八段按文件名顺序拼成完整页面，源码里的 `\\` 是本来就有的字面反斜杠。两个必须知道的约束：
  - **`08-tabs-misc.js` 带着 `</script></body></html>` 收尾**，所以新分片不能排在它后面（页面会以「结尾不在末尾」失败）。新开分片要挑它前面的编号。
  - **单个分片不超过 500 行**（`console-page.test.mjs` 会拦）。`03-tabs-content.js` 放不下时内置指令那块已挪到 `07-tabs-builtins.js`。
  - `console-page.test.mjs` 默认只做结构校验（首尾完整、关键锚点、换行分隔符、内嵌脚本能过 `node --check`、分片行数）；只有设 `PAGE_STRICT=1` 时才与拆分前的备份逐字节比对，**而逐字节比对只是「纯搬迁」时的手段**，主动加功能后必然对不上。
- **换行分隔符只有一个坑，记牢**：`page/*` 是模板字面量，源码里写 `\\n` 拼出来才是浏览器里的**真换行**（`split('\n')` 能按行拆）；写 `\\\\n` 拼出来是字面 `\n`，会让「每行一个」的关键字框把全部内容粘成一行、存盘后再打开就乱。改这些文件时别顺手"修正"看着多余的转义。
- **`el(tag, cls, attrs)` 的第三个参数传数组时表示子节点**，会 append 进去。传对象才是属性。传错不报错，只是元素渲染成空的。
- **加新内置指令必须同时改四张表**，漏哪张都会出「静默」或归类错误：`src/brain-registry.js` 的 `NAME_MAP`（不登记就触发不了，且**完全没有报错**）与 `CMD_CATEGORY`（控制台归类）、`src/builtins/*.js` 里实际的注册键、以及 `src/console/page/03-tabs-content.js` 的 `BDEFS`（控制台开关清单）。排查「指令没反应」时先确认 `NAME_MAP` 里有这个名字。
  > `BDEFS` 的**键**和 `NAME_MAP` 的规范名不是一回事：群管理那批在 `BDEFS` 里用的是拼音键（`mute`/`unmute`/`kick`/`banall`/`unbanall`/`recall`），中文「禁言」「踢出」只是 `label`。在 `BDEFS` 里按中文写键 = 永远匹配不上，且没有任何报错。
- **想让主人改内置指令的文案**：在 `07-tabs-builtins.js` 的 `COPY_TPL` 里加一条，键必须是 `BDEFS` 的键。控制台「内置指令」页会自动出现「复制为预设 / 复制为关键字」按钮，把内置换成一条可编辑的预设，并把原内置自动关掉。**依赖真实数据的指令（签到/积分/抽卡/钓鱼等）不要加**——预设读不到存档，加了按钮等于骗人。
- **事件配置 UI 的键必须和后端一致**：`05-tabs-risk-ai.js` 里 `evEnsure('xxx')` 的键要和 `brain-notice.js` 的 `NOTICE_DEFAULTS` 完全对得上（`welcome`/`leave`/`poke`/`essence`/`admin`/`ban`/`friend`）。写错一个字母不报错，只是配了永远不生效。`console-events.test.mjs` 会直接对着后端源码比对这两份键。
- **`.bat` 文件里不许出现中文。** cmd 是按 OEM 代码页（中文系统是 936/GBK）读 `.bat` 的，不是 UTF-8。
  汉字被解成乱码不算最糟的——某些字节序列会让**下一行被当成命令执行**，
  实测 `share.bat` 直接报 `'发给别人?' 不是内部或外部命令` 然后整个脚本死掉。
  `chcp 65001` 救不了，因为坏掉的是「读 `.bat` 文件本身」这一步。
  规矩：`install.bat` / `start.bat` / `share.bat` 全部纯 ASCII，中文提示交给 Node 输出。
  `share-dist.test.mjs` 里有一条测试专门守这个（检查无非 ASCII 字节、无 BOM）。
- **往 `SECRET_PATHS` 加字段时要一起想清楚回传问题。** 掩码后前端拿到的是空串，
  保存时如果整份 POST 回来，服务端会用空串覆盖真实密码。现在靠 `body.secrets` 显式传密钥、
  服务端只更新密钥路径来避免（见 config-api 的保存逻辑）。加新密钥字段时别绕过这套。
- **「算占位符」的定义只有 `setup.js` 的 `isUnfilled()` 一处。**
  之前 `bootstrap-config.js` 自己硬编码了一份 QQ 号列表，模板把占位号从 `123456789`
  换成 `******` 之后就漏判了，主人权限相关的提示全部失效且不报错。现在两边共用一个函数。
- 排查指令问题时的 handy 手法：把 `client/src/brain-registry.js` 的 `NAME_MAP`（别名→规范名）、`CMD_CATEGORY`（规范名→开关类）、`client/src/console/page/03-tabs-content.js` 的 `BDEFS`（控制台开关清单）三张表和 `BUILTINS` 实际注册键对账，能一次抓出「注册了但触发不了」「归错类」「控制台关不掉」这类问题。**`NAME_MAP` 漏登记的表现是完全静默、不报错**，最难查，务必先看它。
- **「没反应」的第二常见原因：限流，不是 bug**。关键字回复除了自己的 `cooldownSec`，还要过一道**群级间隔** `settings.gates.groupReplyGapMs`（默认见 `config.json`，`brain.js` 里在调 `tryKeyword` *之前* 就拦掉了）。所以同一群里连发两条关键字，第二条会被静默丢弃且不回复——调试时先把 `groupReplyGapMs` 调 0。另一类是 `settings.defaultOff` 默认含 `生日/文娱/互动/联网`，这些分类的新指令要 `/开启 互动` 之类才生效，回复「XX 在本群还没开启」即属此类。
- **可编辑项的权限有三个字段，注意优先级**：`ownerOnly`（仅 `config.json` 的 `adminIds`，群主群管都不放行）> `adminOnly`（+ `permKey` 指定授权项）。控制台里勾一个会自动取消另一个。**「仅管理员」不等于「主人专属」**——这是最容易配错的地方。详见 `client/控制台指令填写说明.txt`。

## 扩展功能

**最简单**：打开控制台 http://127.0.0.1:9632，在「预设指令」里加一条即可（存到 `content.json`，热生效）。

**要写代码**：事件路由在 `client/src/brain.js`。内置指令在 `BUILTINS` 表里注册（键为归一化后的命令名），并在 `brain-registry.js` 的 `NAME_MAP` 里登记中文名/别名：

```js
// brain-registry.js 的 NAME_MAP 里加:
天气: "weather",            // 别名 → 归一化指令名
// builtins/ 里注册:
weather: {
  fn: async (body, args) => {
    await sendText(body, "今天晴，注意多喝水。", "weather");
  },
},
```

> 别忘了在 **`CMD_CATEGORY`**（同样在 `brain-registry.js`）里给 `weather` 归一个类（如 `weather: "联网"`），以及在控制台的 `BDEFS`（`client/src/console/page/03-tabs-content.js`）里加一条，否则控制台关不掉它。不登记类别的话 `/开启`/`/关闭` 和 `/开启` 的可选项列表里都不会出现它（会落到「其他」类被忽略）。`ownerOnly` / `adminOnly` 的指令可以不归类——它们本来就豁免群开关。

所有对外发送统一走 `sendText(body, ...)` / `sendMsg(body, segs)`（内部经 `sender.enqueue()` 防风控队列），**不要绕过它**直接 `gateway.call`（管理/查询类 API 调用除外）。图片/语音等富媒体消息段参考 OneBot 11 标准即可。

## 常见问题

- **launcher 报「provided QQ path is invalid」** → QQ 未安装或注册表路径异常，重新安装 QQ；或改用一键包 `download-napcat.ps1 -OneKey`；
- **双击 start.bat 窗口闪退** → 已修复（批处理内多行 if 块含括号导致 cmd 解析崩溃；现为 CRLF + 无括号文本）。若仍闪退，在项目目录按住 Shift 右键 →「在此处打开 PowerShell 窗口」，执行 `cmd /k start.bat` 打开看红字报错。
- **提示提权 / UAC** → NapCat 需要管理员权限注入 QQ。双击 start.bat 后会弹一次 UAC，点“是”；之后自动用 PowerShell 提权（无需安装 Windows Terminal）。
- **QQ 版本不符** → NapCat 4.18.28 官方适配：9.9.22-40990、9.9.30-48762、9.9.31-49738。若本机 QQ 是其它 build：
  - 基础收发消息通常仍可用；
  - 戳一戳/文件直链等**高级 API 会失败**或登录可能异常 → 把 QQ 安装包版本对齐到上表（推荐 9.9.31-49738），或卸载后改用 `download-napcat.ps1 -OneKey`（内置匹配版本的 QQ+NapCat，并默认关闭自动更新）；
- **客户端连不上** → 先看客户端窗口是否显示 `反向 WS 服务已启动`；确认 `bot\napcat\config\onebot11.json` 与 `client/config.json` 的 url/path/token 一致；
- **登录要输 token / 设备验证** → 新设备首次登录正常现象，在手机上确认即可；
- **AI 不回复 / 一直回兜底话术** → 检查 `client/config.json` 的 `bot.ai.enabled` 是否为 `true` 且 `apiKey` 已填；`baseUrl` 要与服务商匹配（DeepSeek 用 `https://api.deepseek.com/v1`，模型如 `deepseek-chat`）。改完需重启客户端；
- **抽签没有图** → 控制台「抽签图片」里确认目录正确并「扫描预览」；目录里需有 png/jpg 等图片；
- **群管理指令无效** → 这些指令要求 bot 本身是该群管理员/群主；报错信息里会提示；
- **控制台一直显示「连接中…」** → 十有八九是**旧客户端实例还在后台跑**：新实例会因端口 8181 被占用而启动失败，于是你打开的还是旧进程的旧页面。处理：双击 `stop.bat`（或运行 `scripts\stop-client.ps1`）关掉所有客户端，再重新启动；然后按 **Ctrl+F5** 强制刷新。新版状态栏会显示 `端口/PID/构建`，据此可确认看到的是当前实例；若控制台端口被占用，日志会提示实际地址（自动顺延 9633…）；
- **多个群/多人同时发消息，有的没回复** → 同一会话严格排队、不同会话并发发送，慢的大图不会卡住其它会话；若仍无回复，看控制台状态栏的 `队列/丢弃` 与日志：常见原因是该会话刚回过（冷却）、`userRateLimit` 达到上限、深夜静默，或状态栏出现 `软静默ON`（点「重置风控 / 解除软静默」）；重复文本默认不再丢弃（`sameTextGapMs:0`）；
- **抽签很慢** → 签图原图 1~4MB，已自动压缩到约 200KB（首次编码约 100ms）再发送，上传明显更快；慢主要取决于 QQ 服务器上传速度；
- **第一次发消息 / 第一次响应很慢** → 是 NapCat 与 QQ 冷启动、首次建连的正常现象，通常几秒到十几秒，之后恢复正常；
- **发送提示风控/太频繁** → 客户端会自动降速；再把 `minDelayMs`、`groupCooldownMs` 调大；
- **下载失败** → 内置 ghfast.top 镜像；也可手动从 <https://github.com/NapNeko/NapCatQQ/releases> 下载 `NapCat.Shell.zip` 解压到 `bot\napcat\`。

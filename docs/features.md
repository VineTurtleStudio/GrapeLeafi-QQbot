# 功能一览

> 本文是 [GrapeLeafi-QQbot](../README.md) 的详细说明，内容与主 README 同步维护。

## 功能一览

**内置指令**（群聊/私聊都在前面加 `/`，如 `/help`、`/签到`；**群内被 @ 或喊昵称时可以省略 `/`**，例如 `@葡叶酱 禁言 @某某 5分钟` 等同 `/禁言 @某某 5分钟`；不带 `/` 的普通文本不再当成指令执行，会走关键字 / AI / 仅@ 逻辑）

| 指令 | 说明 |
| --- | --- |
| `/ping` | 存活与延迟 |
| `/help` `/帮助` `/求助` | **以图片形式**按类型分组发送帮助：每个类型只列前几条并提示「还有 N 条」，输入 `/help <类型>`（如 `/help 文娱`、`/help 积分`、`/help 抽卡`）可看该类型全部指令与说明；图片生成失败时自动退回纯文字，不会「没反应」 |
| `/运势` | 今日运势（每人每天一次） |
| `/抽签` | 从 `content.json` 指定目录随机抽一张签图并发送（带冷却） |
| `/钓鱼` `/鱼塘` `/卖鱼` | 钓鱼小游戏，仓库与金币持久化在 `client/data/games.json` |
| `/签到` `/等级` `/面板` | 每日签到+积分与光玉 / 等级档案 / 按钮卡片面板。等级图与签到图为 **原神角色面板风格**：左侧深色面板放头像、**葡家等级**进度条和双列属性网格（数值排在文字右侧），昵称右侧跟一枚**等级头衔**；右侧立绘取自该用户已抽到的**卡面**（`card` 图优先、`detail` 图兜底），抽不到卡则回退渐变 |
| `/头衔` `/设置头衔 <起始等级> <文字>` | 看自己的葡家头衔、看全表（`/头衔 列表`）。默认 10 档、每 10 级一档：葡家娃娃 → 葡家在编学生 → 葡家编外奶爸奶妈 → 葡家编外辅导员 → 葡家在编奶爸奶妈 → 葡家在编辅导员 → 葡家在编守门人 → 葡家在编守门百夫长 → 葡家长老会成员 → 葡家分站站长。**群主/群管理员/被授予管理员/主人**在群里发 `/设置头衔` 只改本群（`/设置头衔 重置` 撤掉本群覆盖）；**私聊发则改全局表，只有主人能改**（群主/管理员在私聊会被顶回去并提示去群里发）。也可在控制台「葡家头衔」页直接编辑 |
| `/抽卡 <池> [数量]` `/十连 [池]` | 用**光玉**抽卡。池子可写作品（`ab`）或角色名（`奏`/`由理`/`音无`…），单次最多 10 连。别名 `/十连`→`十连`。例：`/抽卡 ab`、`/抽卡 奏 10`、`/抽卡 10 ab` |
| `/卡池 [池名]` `/保底` | 查看全部卡池与单抽价格 / 查看各池 SSR 与 SR+ 保底进度 |
| `/图鉴 [页数]` `/查卡 <作品> <编号> [详情\|小图]` | 我的卡牌缩略图墙（每页 20 张）/ 查看任意一张卡，末参 `详情`=详情大图、`小图`=结算小图 |
| `/兑换 <数量>` | 积分余额换光玉（1 积分 = `cards.json` 的 `exchange.rate` 倍，当前 **1:1**）。**只扣余额，等级与累计积分不受影响** |
| `/分解 <卡号\|全部>` | 分解重复卡换光玉：`SSR→50`、`SR→20`、`R→5`、`N→1` |
| `/光玉` | 查询光玉余额与当前积分 |
| `/生日` | 查看今天生日的角色与本群开关状态；`/生日 开启`/`/生日 关闭` 打开/关闭本群生日提醒；`/生日 添加 [名字] [MM-DD]` 添加仅本群生效的自定义生日（如 `/生日 添加 小叶子 07-23`）；`/生日 删除 [名字]` 删除本群自定义生日。**默认未开启**，先说 `/生日 开启` |
| `/开启 X` `/关闭 X` | 按「类型」或「单条指令」开关群功能（见下文「群功能开关」）；发 `/开启` 查看可选列表 |
| `/一言` `/诗词` `/冷知识` | 文娱类：每日金句 / 随机诗句 / 冷知识（默认按群关闭，需 `/开启 文娱`） |
| `/今日人设` `/土味情话` `/彩虹屁` `/舔狗日记` `/毒鸡汤` `/时间` | 文娱类：人设 / 情话 / 夸夸（后两者可 `@某人`）/ 文案 / 当前时间（默认按群关闭） |
| `/猜数字` `/塔罗` `/今日人品` `/疯狂星期四` | 互动类：1~100 猜数（`/猜 N` 出招）/ 塔罗牌（`/塔罗 N`，默认 3 张）/ 每日人品 / v50（默认按群关闭） |
| `/敲木鱼` `/功德榜` | 互动类：攒功德（可暴击，存 `merit.json`）/ 功德 Top10（默认按群关闭） |
| `/抽群友` `/轮盘` | 互动类：随机点名 / 俄罗斯轮盘（打中禁言5分钟，需 bot 是本群管理员；默认按群关闭） |
| `/戳一戳 @某人 [类型]` `/比心 @某人` `/点赞 @某人` `/回戳 @某人` | 互动类：**真动作**，走 `group_poke`/`friend_poke`/`send_poke`。**群聊用 `@某人`，私聊直接写 QQ 号**（`/戳一戳 12345678`，私聊里没有 @）。类型可选 `比心`/`点赞`/`心碎`/`666`/`放大招`，以及 9 种 SVIP 花样（`抓一下`/`碎屏`/`勾引`/`手雷`/`结印`/`召唤术`/`玫瑰花`/`让你皮`/`宝贝球`，需 bot 号是 SVIP）。`/比心`、`/点赞` 是 `/戳一戳 @某人 比心|点赞` 的简写。**注意**：花样靠 poke 消息段表达、而消息段无法指定戳谁，所以「action 负责戳到人、消息段负责换花样」是两件事，花样没发出去时机器人会明说「只戳了普通的一下」。**若指令毫无反应，先确认两件事**：① bot 是否在运行；② 互动分类是否在本群开启——`互动` 默认在 `defaultOff` 里，`groupEnabled` 只列了特定群的话其他群一律不放行，此时会回「在本群还没开启」（默认按群关闭） |
| `/拍一拍 @某人` `/捏一捏 @某人` | 互动类：只发文案。QQ 没有独立的拍/捏动作，别误以为会真戳（默认按群关闭） |
| `/天气 [城市]` `/热搜` | 联网类：实时天气（wttr.in 免密钥）/ 全网热点 Top10（默认按群关闭，接口偶发失败会友好提示） |
| `/随机二次元` | 从控制台已启用且标记为非18+的图片 API 中随机取图，失败自动换源；别名：`/随机二次元图片`、`/二次元图片`、`/随机动漫`、`/动漫图片` |
| `/群名片 [名字]` `/群名 [名字]` | 群管理：改某人名片（可 @）/ 改群名；权限同「群管理」 |
| `/我的 [@某人/QQ号]` `/信息 [@某人/QQ号]` | 查询个人资料 / 群成员资料与头衔（走 OneBot API），默认自己 |
| `/群信息 [群名/群号]` | 查询群名称/人数/群主，默认当前群（群里可省略参数） |
| `/头像 [@某人/QQ号]` | 发送头像图片，可省略（默认自己） |
| `/禁言 [@某人/QQ号] [时长]` `/解禁 [@某人/QQ号]` | 群管理，**发送者须是本群管理员/群主或主人**；目标支持 `@某人` 或直接填 QQ 号；时长支持 秒/分钟/小时/天/周（默认10分钟），如 `/禁言 123456 1小时` |
| `/踢出 [@某人/QQ号]` `/全体禁言` `/解除全体禁言` `/撤回`(回复一条消息再发) | 群管理，权限同上 |

> 所有「目标是某人」的指令都同时接受 **@某人** 与 **QQ 号** 两种写法，例如 `/禁言 @某某 10分钟` 与 `/禁言 123456 10分钟` 等价。

> 群管理类指令会先校验发送者身份：**本群管理员/群主**、配置里的 `adminIds`（主人），或被主人**授权**过的账号才执行，否则回复「权限不够」。bot 自身也需要是该群管理员才能执行成功。

**主人与授权（隐藏指令，仅主人可用）**
- 主人 = `client/config.json` 的 `bot.adminIds`（填自己的 QQ 号），拥有全部权限，且不受深夜静默/频率限制。
- `/给予 [@某人/QQ号] 管理员` — 授予「bot 管理员」，等同于本群管理员能用的全部指令；
- `/给予 [@某人/QQ号] 禁言,踢出` — 只授予单个权限，可选：`管理员`/`禁言`/`解禁`/`踢出`/`全体禁言`/`解除全体禁言`/`撤回`（逗号或空格分隔）；
- `/剥夺 [@某人/QQ号] [权限...]` — 剥夺指定权限，不写权限则剥夺其全部；
- `/权限 [@某人/QQ号]` — 查看某人当前的 bot 权限。
- 该授权**只作用于 bot 指令**（相当于 bot 内的白名单），不会给对方真实的 QQ 群管理身份；授权记录持久化在 `client/data/permissions.json`。这些指令不会出现在 `/help` 里（隐藏），非主人发送时被当作普通消息忽略。

> ⚠️ **`/给予` 和 `/发放` 是两个不同的指令，别搞混**：
> - `/给予 @某人 管理员` → **权限**系统（授权对方能用什么指令）
> - `/发放 积分 100 @某人` / `/发放 光玉 500 @某人` → **货币**系统（直接加减积分/光玉）
>
> `/发放` 的完整用法：`/发放 <积分|光玉> 数量 [@某人]`；数量写负数即扣回（`/发放 光玉 -50 @某人`）。两者都是 `ownerOnly`，非主人发送会被静默忽略。

**聊天回复**
- **私聊**：白名单内的人随便聊，非指令内容交给 AI；AI 没配就用兜底话术；
- **群聊 @它 或喊昵称**：后面跟着的如果是可用指令，直接执行（不用再打 `/`，如 `@葡叶酱 运势`）；不是指令则交给 AI；
- **群内是否自动接话**：在控制台「回复设置」里选。默认「自由回复」——群内没被点名也会对关键字/问候词`接话；选「仅 @ 回复」后，群里必须 `@它` 或喊昵称（或输入 `/` 指令）才回复，避免误触发；同页可设「关键字长句上限」（`keywordMaxLen`，0=不限制，默认不限；填 N 则超过 N 字的消息不再触发 包含/正则 关键字，防止长文本误触发）；同页还有「**回复时引用原消息**」（`settings.replyQuote`，默认勾选=沿用协议端「回复某条消息」的引用样式；取消后指令/关键字/AI 回复一律**直接发送不引用**）；
- **指令与预设回复不走 AI**，直接按 `content.json` 的配置回复，零延迟零成本；
- **预设指令支持模板占位符**：回复文案里可用 `{args}`(全部参数)、`{1}~{9}`(第n个参数)、`{rand:1,100}`(区间随机整数)、`{at}`(@回复发送者)、`{target}`(@被@的人，实现「冲 @某人」这类交互指令)、`{targetqq}`、`{qq}`/`{nick}`/`{gid}`、`{date}`/`{time}`，以及**权限类占位符**：`{role}`(发送者身份：主人/管理员/群主/群管理/成员)、`{ifadmin:A|B}`(发送者是 主人/被授予管理员/群主/群管理 时输出 A 否则 B)、`{ifowner:A|B}`(只判是否主人)；还有**动作占位符**：`{ban}`/`{ban:5分钟}`、`{unban}`、`{kick}`(对被@的人执行)、`{banall}`/`{unbanall}`(全体禁言开关)、`{recall}`(撤回你回复的那条消息)，仅群聊且仅管理员执行、文字本身不会显示；还有**卡片/签到类占位符**：`{panel}` 让回复自带官方按钮卡片(签到/钓鱼/运势/等级，协议端不支持时 `/面板` 自动降级为文字列表)、`{signday}` 对触发者执行签到并附一张实时生成的签到卡(头像/等级/积分/连续天数，base64 内联发送，即发即弃不落盘)。例：回复填「{nick} 掷出 {rand:1,6} 点」即可实现 `掷骰` 指令，「已成功灌注 {target} {rand:50,500} 毫升」收到「灌满 @某人」就会把**被@的人**转成 @ 段并回随机毫升数；**`{args}` 可做「传话筒」**：指令名填 `说`、回复填 `{args}`，群里发 `@葡叶酱 说 喜欢你`（或 `/说 喜欢你`）它就原样回「喜欢你」；关键字回复同样支持（无参数变量）。每条指令还可配**别名**（`aliases`，逗号分隔）与帮助简介 `desc`（`/help` 图片里展示）；复杂逻辑指令继续用代码内建（控制台不需覆盖）。
- **HTTP 接口指令**：预设指令可绑定一个 URL，启用后该指令把参数/消息内容（JSON POST 或 GET Query）发给该地址，把**返回内容作为回复**——返回纯文本→直接回；返回 JSON 数组或 `{message}` / `{messages:[...]}` → 每条一条消息，多条第**默认合并转发**成一条（取消勾选则逐条发）。常用于：把文字/图片交给外部服务处理（AI 画图、翻译、OCR、风纪检查、你自己写的脚本接口等），或**仅管理员**的指令作为远程管理操作入口。请求体会带 `command/user_id/group_id/nickname/text/images[]/date/time`，可配 Authorization Token（Bearer）；调用失败会回复失败原因。所有指令仍先过 冷却/权限(仅管理员)/群限制/静默 这些既有闸门。
- **群内自建指令**（每个群独立，互相看不见）：群成员 @bot 说「**添加指令 名字 回复内容**」即可新增，之后在该群直接发「名字」就自动回复对应内容（例：`@bot 添加指令 寄寄 寄寄富` → 群里发「寄寄」回「寄寄富」）；发「**本群指令**」查看本群已有哪些；发「**删除指令 名字**」删除。（等价写法：`新增指令`/`教我`、`移除指令`/`忘记`、`查询指令`/`自定义指令`/`群指令`；回复内容同样支持模板占位符。）保存进 `content.json` 的关键字列表（标记「本群」，限定群=该群）；频率限制：每人 10 秒一条、每天最多 20 条，管理员不受限。
- **关键字回复**：`content.json` 里配的关键词命中就自动接话（可在控制台增删）。**一条回复支持多个关键字**（用 `matches` 数组，控制台里**一个关键字一行**，任一命中就触发；同一行用 `/` 分隔也可，如 `说/复述`；老数据只有 `match` 时以它为准）。**`{args}` 在关键字里=命中词后面的内容**：如关键字 `说`（包含）回复 `{args}`，发「说 喜欢你」就回「喜欢你」（关键字无需 `/` 或 @ 也能触发）。支持**多种触发条件**：`contains`(包含) / 整句(默认) / `useRegex`(正则) / `mentionOnly`(仅被@时) / `adminOnly`(仅主人或管理员触发)；命中后可用**随机多条**（每次随机取一条）、**图片**（本地路径或 http 链接）或**整句复读**（`repeat:true` 回触发句），还可用 `excludeWords` 设置命中即忽略的排除词。冷却填 `0` 表示**不冷却**（未填默认 60 秒，预设指令默认 5 秒）。

- **关键字随机发本地图库**：关键字卡片里除「图片」外还有「**图库目录**」。填目录后每次命中会从**整个图库随机抽一张**发出来（纯随机，不保证不连续重复）。规则：
  - **递归扫描**全部子文件夹，支持 `png` / `jpg` / `jpeg` / `gif` / `webp`（大小写不敏感），非图片文件自动忽略；最大深度 6 层、最多 5000 张。
  - **可填多个目录**，用**分号或换行**分隔，几个目录的图片会**混在一起**随机；适合「角色图库」「作品图库」分别建不同关键字。
  - 目录按你的习惯分类即可，**建议直接用文件夹分类而不是数据库**：`图库\作品名\角色名\xxx.jpg`。图库本身已经是文件，文件夹分类零维护、拖进来就生效、备份/迁移就是拷目录；只有当你需要「每张图带标签/权重/冷却/单独开关」这类元数据时，才值得上数据库（那时把索引存 `data/` 下的 json 即可，原图仍然留文件夹）。
  - 文件列表**缓存 60 秒**，所以刚放进新图最多一分钟生效；删图同理。想立刻生效就等一分钟，或重启客户端。
  - 「图片」和「图库目录」**同时填时以图库目录为准**。只填图库目录、不填文字也可以触发（修掉了以前纯图片关键字不响的问题）。
  - 抽中的图会走和抽签图一样的处理：压到 **1080px 宽 / JPEG q82** 后以 `base64://` 内联发送，不落地、不受本地路径权限影响。
  - 卡片上有「**扫描预览**」按钮，保存前可以先看扫到几张图、有没有进错目录。
- **分时段问候（早安/晚安等）**：预设指令与关键字都可以给「早 / 午 / 晚 / 夜」四个时段分别填文案（早 5-11、午 12-17、晚 18-21、夜 22-4，边界与代码 `timeReplyFor` 一致），回复时按**服务器当前时间**自动选用对应文案，没填的时段用「回复(默认)」兜底。`content.json` 里已默认配好「早安」「晚安」「晚上好」三条**关键字**（注意是关键字，**不带 `/`**，直接在群里发「早安」就触发，不是 `/早安` 指令）——但这三条只存在于**你自己这份** `client/data/content.json`；`share.bat` 生成的去个人化模板会把关键字和预设指令整块清空，拿到包的人自己在控制台「关键字回复」页加。

**AI 对话**：在 `client/config.json` 的 `bot.ai` 打开（`enabled:true` 且填 `apiKey`）。采用 OpenAI 兼容协议，改 `baseUrl`/`model` 即可对接 DeepSeek、Kimi、通义、OpenAI 等任意兼容服务，无需装额外依赖。

AI 会**读当前会话的聊天记录**再回答：被 @ 提问时，之前的群聊（或你们自己的私聊）会作为背景一起发给模型，机器人自己说过的话也会标成「你」留在记录里，所以它能接上「我刚才说的那个」这类追问，而不至于每轮都像第一次见面。相关开关：

- **什么时候问**（`bot.ai.trigger`）：`mention` 只有被 @ 时（默认，最省 token）/ `keyword` 消息以触发词开头 / `active` 群里说话就问（很吵）/ `off` 完全闭嘴。
  触发词是 `bot.ai.triggerWords`（默认 `["问","ai","chat"]`）。**中文不必加冒号**——「问今天天气」就会触发；而「这个问题」不会，因为触发词后面只剩 1 个字，达不到判定下限。英文习惯写 `ai: xxx` 也一样能触发。
- **读多少**（`bot.ai`）：`contextTurns` 每次最多带几条（默认 12）、`contextMinutes` 记录记多久（默认 30 分钟）、`rememberTurns` 记住自己说过几条（默认 6）、`maxContextChars` 单条最多几个字（默认 200，超出截断，群里有人贴日志时很有用）、`maxReplyChars` 单条回复超长自动拆条（默认 0=不拆）。
- **给谁用**（`bot.ai`）：`groups` 只在这些群启用（留空=所有群）、`privateEnabled` 私聊是否可用、`replyToBot` 回复机器人消息时是否也当作提问。
- **说话方式**（`content.json` 的 `content.ai`，控制台「AI」页）：`systemPrompt` 人设、`style` 语气风格、`rules` 硬性规矩、`includeContext` 是否把聊天记录一起发过去。

> **隐私**：开着 AI 且 `includeContext` 为真时，**群里的聊天内容会被发送给你配置的那个第三方 AI 接口**。介意就别开，或者只在可信的小群里开、其余群加进 `bot.ai.groups` 白名单。控制台「AI」页有一键试聊，能直接看到实际发出去的提示词长什么样。

> **优先级**：内容页配的「关键字自动回复」比 AI 早生效。像默认的「在吗」「你好」这类关键字，机器人会先按预设回一句，AI 不会被调用 —— 这是既有设计，不是故障。

> **没回话时先看日志**：被 AI 会话间隔（`bot.ai.cooldownSec`，默认 20 秒）或可选的 `aiReplyGapMs` 挡住时，机器人会保持沉默（避免刷屏），但「日志」页会打一行说明。`aiReplyGapMs` 已按「群/私聊 + 用户」分开计，群里的回复不会再挡住私聊。

**定时群提醒**：`content.json` 的 `schedule` 里配置每天固定时间向指定群推送（每条形如 `{id, time:"07:00", groups:[群号], message, enabled}`，轮询间隔 `scheduler.checkEverySec` 默认 20 秒）。当前已启用 2 条：07:00 与 22:00，各推 1 个群。控制台「定时提醒」页可增删改。

**生日提醒（Key 社）**：内置 **136** 位 Key 社角色生日，覆盖 **11** 部作品（AIR / Kanon / CLANNAD / Little Busters! / Summer Pockets / Rewrite / Heaven Burns Red / Charlotte / LOOPERS / Kud Wafter / LUNARiA；注意 Little Busters 的正确写法带叹号 `!`，`Little Busters!` 是 Key 社同一作品，不要当成两部）。每天 `birthdays.time`（默认 `00:00`）向**已开启的群**自动推送当日生日祝福（文案 `birthdays.notice` 可自定义，占位符 `{name}` `{series}` `{date}`）。**默认不主动打扰任何群**——群内先发 `/生日 开启`（同一命令也会让 `/生日` 查询可用），`/生日 关闭` 即关；群内可用 `/生日 添加 [名字] [MM-DD]` 添加自定义生日（仅该群生效、私密不过群里的人仍能看到祝福），控制台「生日」页可维护全部数据/开关/推送时间/开启群。开启的群会记录在 `birthdays.groups` 里（示例模板为空，需自行填自己的群号）。

**积分、光玉与等级**（`client/data/checkins.json` + `client/data/cardgame.json`，两套货币互不干扰）：

| 名称 | 存哪 | 怎么涨 | 怎么花 | 会不会影响等级 |
| --- | --- | --- | --- | --- |
| **积分余额** `points` | `checkins.json` | 签到（`+10 + min(连续天数-1, 10)`，即 10~20/天）、`/发放 积分 +n` | `/兑换 <n>` 换光玉、`/发放 积分 -n` | **不会** || **累计积分** `earned` | `checkins.json` | **只有签到才加**（`/发放 积分` 不算，那是余额不是累计），**只增不减** | 不可消费 | **是升级的唯一依据** |
| **光玉** `stones` | `cardgame.json` | 签到赠送（`min(4+连续天数, 10)`，即 5~10/天）、`/兑换`（1 积分 = `cards.json` 里 `exchange.rate` 倍光玉，当前 **1:1**）、`/分解` 重复卡 | `/抽卡`（5 光玉/抽，单次最多 10 连）、`/发放 光玉 -n` | **不会** |

等级走**游戏式经验条**，只吃 `earned`：`Lv.N → Lv.N+1` 需要 `100 × N` 累计积分，升级后余量带入下一级（Lv1→2 需 100，Lv2→3 需 200，Lv3→4 需 300，以此类推）。所以**把积分全花掉也不会掉级**，而**升级也永远不会去扣你手里的余额**——两者完全独立。`/等级` 看档案，`/help 积分` 看规则说明。

> 存档里早期只有 `points`、没有 `earned`（也没有已废弃的 `career`）的老档案，会在客户端加载时自动按 `max(earned, career, points)` 回填并落盘，避免「消费光余额后，下一次签到把缩水后的余额固化成新基准」导致进度回落。

### 存档的耐久性保障

所有 `data/*.json` 都经由 `client/src/storage.js` 这一个入口读写，因此数据安全策略只需在一处实现。目前具备：

| 机制 | 做法 | 防的是什么 |
| --- | --- | --- |
| **原子写** | 先写同目录 `.tmp`，fsync 后 `rename` 覆盖 | 读到写了一半的文件；崩溃损坏主文件 |
| **落盘同步** | rename 前后分别 fsync 数据文件和目录项 | 掉电后「文件名更新了但内容是空的」 |
| **滚动备份** | 覆盖前自动备份到 `data/backups/<文件名>/<时间戳>.bak`，**保留最近 5 代** | 逻辑错误、误编辑、磁盘故障导致的数据丢失 |
| **损坏即停** | 解析失败时把坏文件改名成 `<文件名>.corrupt-<时间戳>` 并**中止启动**，绝不静默回退成空数据 | **静默清零**——这是最隐蔽的数据丢失方式：文件坏了 → 空状态启动 → 第一次保存把坏文件覆盖 → 原始数据永久消失 |
| **脏检查** | 内容与磁盘一致时跳过写入 | 无谓的全量重写（`content.json` 有 3MB） |
| **版本门** | `checkins.json` / `cardgame.json` 顶层 `__v` 决定是否跑迁移 | 每次启动都把老档案按兜底值重算一遍这类隐式改写 |

**恢复步骤**：存档报「解析失败」时，先看 `data/backups/<文件名>/` 下时间戳最新的那一份，把当前文件改名留档（别直接删），再把备份复制成原文件名，然后启动。程序会在报错信息里直接给出备份目录路径。

**备份限流**：同一文件 5 分钟内只备份一次（可用环境变量 `BOT_BACKUP_INTERVAL_MS` 调，`BOT_BACKUP_KEEP` 调保留代数）。这是为了避免高频保存时把 I/O 全花在复制上——`content.json` 单份就 3MB，3MB × 5 代每次都复制不可接受。注意这个限流意味着**进程刚启动的前 5 分钟内还没有备份**，那期间只有原子写保护。

**故意没做校验和清单**：这些存档需要人工手改，一改就与清单不符，天天误报等于没报警。损坏检测交给解析校验，覆盖真实的截断/损坏场景。

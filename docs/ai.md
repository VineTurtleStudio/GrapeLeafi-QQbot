# AI 对话与推理模型

> 本文是 [GrapeLeafi-QQbot](../README.md) 的详细说明，内容与主 README 同步维护。

## AI 总是自言自语（思考过程发到群里）

GLM-4.5 及以上、DeepSeek 的推理型号（`deepseek-reasoner` 等）、Qwen3 / QwQ 这类**推理模型**，回答前会先生成一段「思维链」再给正文。它占的是 `maxTokens` 的预算，而且**只适合自己看**——发进群就是机器人突然开始长篇大论地自言自语。

### 现在的默认行为

程序从三个层面保证发进群的一定是最终答复（默认全开）：

| 层面 | 配置项 | 作用 |
| --- | --- | --- |
| 请求 | `bot.ai.noThinking`（默认 `true`） | 在请求里带上各家的「关闭思考」参数，让模型一开始就不思考 |
| 提示词 | 自动 | system 提示词明确要求「只输出最终答复，不要输出思考过程」 |
| 清洗 | `bot.ai.hideThinking`（默认 `true`） | 把残留的 `<think>…</think>` 等内容从回复里剥掉，**这一层是最终保险** |

关键一点：程序**不会**把 `reasoning_content` 当成回复。模型只返回思考、正文为空时，会重试或给出明确报错，而不是把思维链发出去。

### 按模型区分的「关闭思考」参数

各家参数不一样，写错了会被接口用 400 拒绝，所以程序按模型自动选择：

| 模型 | 请求里加的参数 |
| --- | --- |
| GLM-4.5 / 4.6 等 | `thinking: { type: "disabled" }` |
| **GLM-5.3、GLM-4.7** | **不发**（强制思考模型，硬发 `disabled` 会 400） |
| DeepSeek | `enable_thinking: false` |
| Qwen（百炼官方） | `enable_thinking: false` |
| Qwen（vLLM / SGLang / 自建） | `chat_template_kwargs: { enable_thinking: false }` |

你在 `bot.ai.extraBody` 里显式写了 `thinking` / `enable_thinking` / `chat_template_kwargs` 时，程序不会覆盖你的值。

### 如果群里还是出现了思考过程

按这个顺序查：

1. **打开设置页「思考过程」分区的两个开关** —— 尤其第二个「剥掉回复里的思考过程」。自建 vLLM / SGLang 常常**忽略**「关闭思考」参数，只有这一层能兜住。
2. **调大 `maxTokens`** —— 它是「思考 + 正文」共用的预算。推理模型光思考就可能吃掉 600 的全部预算，于是**正文为空**。非推理模型建议 1000~2000，推理模型建议 2000 以上。程序遇到「只有思考没有正文」会自动放宽到最多 8000 重试一次（日志里会写 `放宽到 N 重试一次`），所以这一条只影响回复长度，不影响能不能发出话。
3. **换成不思考的模型** —— 群里闲聊没必要用推理模型。推荐 `deepseek-chat`、`glm-4-flash`、`glm-4-air`、`glm-4-plus`。
4. **用控制台「AI → 试聊」确认** —— 试聊会分成三栏显示：**真正会发到群里的内容**、**模型的独立思考字段**（标注「永远不会发进群」）、以及**模型原话**。前两栏不一致就说明清洗层正在工作，是正常的。

### 排查日志

日志里会看到这几条：

- `[llm] 模型只返回了思考过程、正文为空（maxTokens=600 不够），放宽到 2400 重试一次` —— `maxTokens` 给小了，按第 2 条调大；
- `[llm] <模型> 是强制思考模型，不发 disabled 参数` —— 该模型关不掉思考，靠清洗层兜底；
- `[llm] 请求带着 chat_template_kwargs 关闭思考` —— 自建网关场景下的正确提示。
